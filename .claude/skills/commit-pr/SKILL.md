# commit-pr

## 이 스킬이 하는 일

Git으로 뭔가를 "제출"하는 두 순간 — 커밋과 PR — 의 규칙을 정한다. 상황에 맞는 참조 **하나만** 읽는다.

## 상황 판단

| 상황 | 참조 파일 |
| --- | --- |
| 스테이징된 변경을 커밋 메시지로 정리 | [`references/commit-message.md`](references/commit-message.md) |
| 브랜치 변경사항을 PR로 올리기 | [`references/pr-description.md`](references/pr-description.md) |

둘 다 필요한 흐름(예: 마지막 커밋 후 바로 PR)이면 순서대로 하나씩 연다 — 동시에 열지 않는다.

## 공통 규칙

- 커밋 메시지 설명, PR 안의 커밋 목록 모두 **영어**로 쓴다. type/scope/티켓 번호 표기 방식은 두 참조 파일이 공유한다.
- `git commit` · `git push` · PR 생성은 로컬 운영 규칙(`CLAUDE.md`)의 "절대 금지(명시적 요청 없으면)" 항목이다 — 사용자가 명시적으로 요청했을 때만 실행한다. 이 스킬은 초안을 만들고 확인받는 것까지고, 실행은 확인 이후다.
- 브랜치명에서 티켓 번호를 추출하는 방식은 두 참조 파일에서 동일하다 (`feature/KDS-2902_khg` → `KDS-2902`) — 한쪽에서 이미 추출했으면 다시 묻지 않는다.

## 완료 후

커밋이면 커밋 SHA와 메시지 한 줄을, PR이면 PR URL을 보고한다.
