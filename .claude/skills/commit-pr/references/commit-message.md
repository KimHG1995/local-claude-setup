# 커밋 메시지 작성

`commit-pr` 스킬에서 "커밋 메시지를 정리하는 상황"으로 판단됐을 때만 읽는다.

## 형식을 어디서 정하는가

**형식을 이 파일에 박아 두지 않는다.** 저장소마다 다르기 때문이다. 아래 순서로 정한다.

1. **명시된 컨벤션** — 저장소의 `CONTRIBUTING.md`, `.gitmessage`, 프로젝트 `CLAUDE.md`, 또는 사용자가 이 대화에서 지정한 것. 있으면 그것이 최우선이다.
2. **이력에서 관찰한 것** — 1이 없으면 아래 스크립트로 실제 커밋에서 뽑는다.
3. **되물음** — 1도 2도 정하지 못하면 **추측하지 않고 사용자에게 묻는다.**

```bash
bash .claude/skills/commit-pr/scripts/derive-git-convention.sh --mode commit 5
```

exit `0`은 관찰 자료 확보, `2`는 이력 근거 부족, `1`은 조회/입력 실패다. 명시된 지침이나 대화에서 이미 정한 항목은 이력 부족으로 되묻지 않는다. 남은 미정 항목만 확인한다. 실패를 이력 없음으로 취급하지 않는다. 자세한 옵션은 [helper 계약](helper-contract.md)을 따른다.

되물을 때는 관찰한 사실을 먼저 보이고 묻는다. "커밋 규칙이 뭔가요"가 아니라 "최근 커밋이 한국어 3건, 영어 2건으로 섞여 있습니다. 어느 쪽으로 맞출까요"처럼 묻는다.

## 절차

### 1. 컨벤션 확정

위 순서로 정한다. 확정 전에 메시지를 쓰지 않는다.

### 2. 티켓 번호

명시된 티켓 규칙을 우선한다. `feature/ABC-2902_ab`의 `ABC-2902`처럼 현재 브랜치와 요청에서 티켓을 확인한다. 이력에 티켓이 없다는 사실은 금지 규칙이 아니다. 표기 사례가 있으면 참고하고, 현재 티켓의 포함 여부, 위치가 지침으로 정해지지 않으면 그 항목만 확인한다.

### 3. 변경사항 파악

```bash
git diff --staged --stat
git diff --staged
```

스테이징된 파일이 없으면 "`git add` 후 다시 실행하세요"를 출력하고 종료한다.

### 4. 커밋 분리 여부

스테이징 내용이 논리적으로 다른 단위를 포함하면 분리를 제안한다.

- 새 파일 추가와 기존 파일 수정이 서로 독립된 목적을 갖는 경우 (같은 기능에 필요한 변경은 함께 둔다)
- 두 개 이상의 무관한 모듈이 변경된 경우
- 기능 추가와 리팩토링이 섞인 경우

**제목과 실제 변경 파일을 대조한다.** 제목이 말하는 것과 그 커밋이 건드린 파일이 어긋나면 제목을 넓히지 말고 커밋을 나눈다.

분리 제안에 쓰는 예시 메시지도 1에서 확정한 형식으로 쓴다.

### 5. 초안 제시

명시된 길이 제한을 따른다. 이력의 길이는 참고치이며 관찰된 최대값을 강제 제한으로 만들지 않는다.

body는 꼭 필요한 부연이 있을 때만 쓴다. 템플릿이나 섹션 헤더를 넣지 않는다.

### 6. 확인 후 실행

초안을 보여 주고 "이 메시지로 커밋할까요"를 확인받는다. 수정 요청이 있으면 반영하고 다시 확인받는다.

`git commit`은 [`git.md`](../../../rules/git.md)의 승인 게이트 대상이다. 확인 없이 실행하지 않는다.

## Anti-pattern

- ❌ **이력을 보지 않고 형식을 가정하는 것.** 이 파일이 형식을 정해 주지 않는 이유가 그것이다.
- ❌ 명시된 규칙까지 이력 부족을 이유로 되묻거나, 남은 미정 항목을 추측으로 확정하는 것.
- ❌ 되물을 때 관찰 사실 없이 "어떻게 할까요"만 묻는 것. 무엇을 관찰했고 무엇이 안 정해졌는지 같이 보인다.
- ❌ 두 개 이상 모듈이 섞였는데 분리 제안 없이 하나로 묶는 것.
- ❌ 확인 없이 `git commit`을 실행하는 것.
- ❌ 리뷰 중 나온 수정을 `amend`나 `rebase`로 덮는 것. 추가 커밋으로 쌓는다.

## 검증

- [ ] 컨벤션을 명시된 것 또는 이력에서 확정했는가? 가정하지 않았는가?
- [ ] 명시된 규칙으로도 정해지지 않은 항목만 확인했는가?
- [ ] 제목이 실제 변경 파일과 맞는가? 어긋나면 커밋을 나눴는가?
- [ ] 사용자 확인을 받은 뒤에 실행했는가?
