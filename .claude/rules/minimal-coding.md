# 최소주의 코딩

`paths`가 없어 매 세션 상시 로드된다. 여기 두는 이유는 이 파일이 정하는 것이 파일 유형에 딸린 convention이 아니라 **무엇을 만들지 정하는 자세**라서다. 파일이 아직 없을 때 필요하고, `paths`를 걸면 subagent에 상속되지 않아 정작 코드를 쓰는 쪽에 닿지 않는다.

상시 로드라 분량 자체가 비용이다. 파일 유형별 convention은 [`code-quality.md`](code-quality.md)와 [`nestjs.md`](nestjs.md)로 내린다.

## 게으름 사다리

문제를 끝까지 이해한 **뒤**, 먼저 걸리는 칸에서 멈춘다.

1. 애초에 존재할 필요가 있나? 투기적 필요는 건너뛰고 그 사실을 한 줄로 밝힌다.
2. 코드베이스에 이미 있나? 짜기 전에 grep한다.
3. 언어 표준 라이브러리로 되나?
4. 플랫폼 네이티브로 되나? 앱 코드보다 DB 제약, JS보다 CSS.
5. 기설치 의존성으로 되나? 몇 줄로 될 일에 새 의존성을 넣지 않는다.
6. 한 줄로 되나?
7. 그제서야 동작하는 최소 코드.

두 칸 다 되면 위 칸을 잡는다.

**사다리는 해법만 줄이지 이해는 못 줄인다.** 바꾸는 모든 파일과 실제 흐름을 먼저 추적한 뒤에 칸을 고른다. 엉뚱한 위치의 최소 diff는 게으름이 아니라 두 번째 버그다.

**버그 수정은 증상이 아니라 근본을 겨냥한다.** 고치기 전 대상 함수의 모든 호출부를 grep한다. 티켓이 짚은 경로만 패치하면 나머지 호출부는 깨진 채 남는다.

## 요청하지 않은 것을 만들지 않는다

- **요청 안 한 추상화 금지** — 구현 하나뿐인 인터페이스, output 하나뿐인 팩토리, 안 바뀌는 값의 config, 호출부가 하나뿐인 helper, 값만 담는 클래스, 호출부에서 넘기지 않는 기본값 파라미터. 이름을 붙여 밖으로 빼기 전에 호출부에 그대로 두고 읽어 본다.
- **"나중을 위한" 보일러플레이트와 스캐폴딩 금지.** 추가보다 삭제를 택하고, 영리한 코드보다 지루하고 뻔한 코드를 택한다.
- **요청 안 된 hardening 금지** — 계획이나 위임에 없던 방어 가드, 길이 상한, 정규화, fallback, retry를 넣으려면 그것이 막는 실패를 **실제로 관찰한 근거**를 제시한다. "합리적으로 보인다"는 근거가 아니다.
- **의도적 단순화는 주석으로 표시한다.** 알려진 천장이 있는 지름길이면 천장과 업그레이드 경로를 같이 적는다. 무지가 아니라 의도임을 드러낸다.

## 깎지 않는 것

신뢰경계에서 입력을 검증하는 일, 데이터 유실을 막는 에러 처리, 보안, 명시적으로 요청한 일은 사다리 대상이 아니다.

**신뢰경계 = 통제 밖에서 값이 들어오는 지점**이다. HTTP 요청, 파일, 외부 API 응답, 역직렬화, CLI 인자가 해당한다. 같은 코드베이스 안의 내부 호출부는 신뢰경계가 **아니다**. 내부 함수 진입부의 null 가드나 타입 가드는 이 조항이 요구하는 것이 아니라 사다리 1칸의 대상이다. **경계에서 한 번 검증하고 안쪽은 그 불변식을 신뢰한다.** 방어 가드를 겹겹이 쌓으면 진짜 경계가 어디인지 흐려진다.

이 프로젝트에서 그 경계가 어디이고 무엇으로 검증하는지는 [`nestjs.md`](nestjs.md)가 정한다.

**명시된 복수 항목("N개 다 하라")은 반드시 해야 하는 최소 범위다.** 일부만 하고 멈추면 지시 위반이다. 위험한 항목은 잘라내지 말고 안전장치로 완성한다. 단 rules가 요구하는 정지(승인 없는 데이터 변경, 보호 branch)는 축소가 아니라 게이트다.

## 되돌리거나 지울 때

- **접근을 바꿔 되돌렸으면 그 시도의 잔재를 걷어낸다.** 되돌린 파일 목록으로 grep해 남은 상수, 분기, import, 필드를 찾는다. 파일을 원상복구해도 그 시도에 맞춰 다른 파일에 넣은 것은 되돌아오지 않는다.
- **결정을 기록한 주석을 지우면서 그 결정을 뒤집지 않는다.** 지우려는 주석이 "왜 이렇게 하지 않았는지"를 적어 둔 것이면 멈추고 확인한다. 그 결정은 이 변경의 범위 밖에서 내린 것이다.
