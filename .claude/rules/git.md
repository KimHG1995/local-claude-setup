# Git

`paths`가 없어 상시 로드된다. 분량을 짧게 유지한다.

**커밋 메시지의 형식은 여기서 정하지 않는다.** 저장소마다 다르고, 지금 작업 중인 저장소의 실제 이력에서 뽑는 것이 맞다. 그 절차는 `commit-pr` 스킬이 맡는다. 이 파일은 저장소와 무관하게 늘 참인 것만 둔다.

## 커밋

- **커밋 title과 실제 변경을 대조한다.** title이 말하는 것과 그 커밋이 건드린 파일이 맞는지 확인한다. 어긋나면 title을 넓히지 말고 커밋을 나눈다.
- **리뷰 중 나온 수정은 추가 커밋으로 쌓는다.** amend나 rebase로 덮지 않는다. 리뷰어가 본 이력을 보존한다.
- 스테이징되지 않은 변경까지 끌어와 커밋 범위를 임의로 넓히지 않는다.

## Branch

- **branch는 로컬 base에서 만든다.** `git checkout -b <이름> <base>`. `origin/<base>`에서 분기하지 않는다.
- **보호 branch(`main`, `master`, `develop`, `stage`, `release`)에 직접 commit하거나 push하지 않는다.** 먼저 feature branch로 분기한다. 설정 저장소처럼 main 직접 커밋이 정상 워크플로인 곳은 예외이고, 그 판단은 사용자가 한다.
- worktree는 사용자가 명시적으로 요청할 때만 쓴다. 기본은 현재 디렉터리다.

## Push

- **force push는 사용자가 명시적으로 요청할 때만 한다.** 그때도 `--force`가 아니라 `--force-with-lease`를 쓴다. 원격이 전진했으면 push가 거부되어 타인 커밋이 사라지는 것을 막는다.

## 승인 게이트

`git commit`, `git push`, PR 생성은 사용자가 명시적으로 요청했을 때만 실행한다. 초안을 만들어 보여 주는 데까지가 요청 없이 할 수 있는 범위다.
